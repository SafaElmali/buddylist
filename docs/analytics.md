# Analytics

Two things are counted, in one [PostHog](https://posthog.com) project:

- **The landing page**, its changelog, its sponsor page and its docs: their visits, and who goes on to download.
- **The app**: that it was opened, and which of its features were used.

Both are anonymous. Neither sends anything you or an agent wrote, nor the name of a folder, file, branch or contact.

## Setting it up

Until a build is given the project's token, it counts nothing anywhere: the page is built without PostHog, and the app sends nothing. Only the release and the site's deploy are given it, so a build of anyone else's, a contributor's or a fork's, counts nowhere.

1. In PostHog, copy the project's **token** from **Settings → Project**. It starts with `phc_`.
2. Put it in the repository variable `POSTHOG_KEY`, under **Settings → Secrets and variables → Actions → Variables** on GitHub. The build of a release writes it into the app (`services()` in [`scripts/build-app.js`](../scripts/build-app.js)), and the site's deploy into the pages. The token only lets counts in and reads nothing back, so it is no secret. A project in the EU also needs `POSTHOG_HOST` in [`src/shared/analytics.js`](../src/shared/analytics.js) changed to `https://eu.i.posthog.com`.
3. In PostHog, turn on **Settings → Web analytics → Cookieless server hash mode**. Without it PostHog drops every count from the page.
4. In PostHog, set **Settings → Project → General → IP data capture configuration** to discard client IP data. PostHog then keeps the country and city a count came from, and not the address.
5. Deploy the page (`npm run deploy:site`) and [release the app](releases.md).

## What the page counts

Every page loads PostHog's library, started by [`scripts/site-analytics.js`](../scripts/site-analytics.js). Named link clicks are counted by [`site/site-counts.js`](../site/site-counts.js), shared by the landing page, changelog, docs and sponsor page. It keeps nothing in the browser: no cookie, and nothing in local or session storage. PostHog tells one visitor from the next by a hash of the address and browser, made with a secret that it throws away every day. So a visitor who comes back the next day counts as a new one.

| Count                   | When                                                                               | What it says                                                      |
| ----------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `$pageview`             | the page is opened                                                                 | where the visitor came from, the browser and the size of screen   |
| `$pageleave`            | the page is left                                                                   | how far down it was read                                          |
| `$autocapture`          | a link or button is clicked                                                        | which one                                                         |
| `download clicked`      | a **Download** link is clicked                                                     | `from`: `header`, `hero`, `steps` or `outro`                      |
| `github clicked`        | the **GitHub** icon or the changelog's **All downloads on GitHub** link is clicked | `from`: `header` or `releases`                                    |
| `coffee clicked`        | a **Buy me a coffee** link is clicked                                              | `from`: `header`, `feedback`, `footer` or `sponsor`               |
| `sponsor clicked`       | a **GitHub Sponsors** or **Become a sponsor** link is clicked                      | `from`: `tile` or `company`                                       |
| `x clicked`             | the header's **X** icon, or **Or get in touch first** on the sponsor page          | `from`: `header` or `company`                                     |
| `product hunt clicked`  | the landing page footer's **Product Hunt** link is clicked                         | `from`: `footer`                                                  |
| `release notes clicked` | the landing page’s **New** pill is clicked                                         | `from`: `hero`; no conversation, account or fallback rule details |
| `tour played`           | the visitor starts the tour with sound; muted autoplay is not counted              | `from`: `play` or `sound`                                         |

| `feedback sent`         | the feedback form's report went out                                                | `kind`: `feedback`, `bug` or `request`                            |

Nobody is recorded, and the [live demo](browser-preview.md) under `demo/` counts nothing. A report's words, address and picture go to the Worker alone, as [Feedback, bugs and requests](feedback.md) describes.

Every count also says which version of the app it is from (`app_version`), the system and its version (`$os`, `$os_version`) and the kind of processor (`arch`).

- **Who a count is from** is a random id, made up the first time the app counts anything and kept in `messenger.json` as `installId`. It says nothing about the computer or who uses it, and PostHog keeps no person for it.
- **Only the installed app counts.** A run from the source (`npm start`) and the demo (`npm run demo`) send nothing.
- **Counts go out together**: half a minute after the first one, or as soon as twenty wait. `app installed` and `app opened` go out at once. Counts that can't be sent, say without a connection, are gone.

## Turning it off

In the contact list, untick **Tools → Share anonymous usage data**. Nothing is sent from then on, and counts that were still waiting are dropped. It is `shareUsage` in the app's settings, and on until someone turns it off.

The landing page tells visitors about both in its FAQ, under "Does the app send anything about me?". Keep that answer and the tables above true to what is counted.

## Reading the numbers

Everything is read in PostHog:

- **Web analytics** has the page's visitors, where they came from and which pages they left from.
- **New installs**: `app installed`, counted by week.
- **Getting going**: a **funnel** from `app installed` to `contact added` to `message sent` is how many new installs get as far as talking to an agent, and where the rest stop. Someone already signed in to their agent in a terminal has no `signed in`, so it is no step of its own.
- **Product analytics → Trends**: `message sent` counted by unique users is how many installs were really used that day or week. `app opened` counts the ones that were only started too. Break `app opened` down by `app_version` to see who has updated.
- `message sent` broken down by `provider` is which agents are talked to, and by `agents` how much of it is in group conversations.
- A **funnel** from `$pageview` to `download clicked` is how many visitors download. The page's visitors and the app's installs are not the same ids, so a funnel can't follow one person from the page into the app.

A run from the source counts once it is told where to send, and which project to count in:

```bash
BUDDYLIST_ANALYTICS_URL=https://us.i.posthog.com POSTHOG_KEY=phc_<token> npm run demo
```

Use a project of your own for this. The counts then show up in PostHog under **Activity** within a minute. Any other address gets the same `POST /batch/`, for a server of your own to print, with any token.

For the page, `POSTHOG_KEY=phc_<token> npx --yes wrangler@4 dev --port 8787` serves it with counting. Without the token it is built with none.

## Counting something more

- **A request a window makes**: add its channel to `COUNTED` in [`src/main/analytics.js`](../src/main/analytics.js), with the name it is counted under. It is counted once the request was answered, and nothing it was asked with is passed on. Its `about` can add to the count from the storage or the answer, or say `null` when the request was answered without the feature being used, like a sign-in that was called off.
- **Something a window does by itself**, that makes no request of its own, such as a picture opened over the window: add its name to `USED` in [`src/main/analytics.js`](../src/main/analytics.js), with what it may say and the values that can be, and have the window call `api.app.used('what happened', { what: 'one of them' })`. Anything else it says is left out.
- **Anything else in the app**: `analytics.capture('what happened')` where it happens.
- **A website link**: add its attribute and event to `LINKS` in [`site/site-counts.js`](../site/site-counts.js), then put the attribute on each link with its position as the value. Every page loads this shared script.
- **Anything else on the page**: import `count` from `site-counts.js` and call `count('what happened')` where it happens, as [`site/site.js`](../site/site.js) does.

Name a count after what happened, in lower case: `terminal opened`. Then add it to the table above. `test/analytics.test.js` stops when a count of the app is missing here, and when a request of a window is neither counted nor listed in its `NOT_COUNTED` with the reason it isn't: a new request is one or the other.
